### Задание 1 **(2)**
*Оцените работу следующих фрагментов программ. Какие из них обладают неоднозначным поведением? Почему?*
```
int x=10, y=3;
std::cout << std::min(x=15, x+y);
```
```
int x=10, y=3;
x=15, y+=x, x+=y;
```
```
int x=10, y=9;
if (x>y++ && y++>9)
  cout << "yes" << endl;
cout << y;
```

*Тексты программ разместите в папке с номером задания*

**Решение.**

**Фрагмент 1 — поведение неоднозначное.**

```cpp
int x = 10, y = 3;
std::cout << std::min(x = 15, x + y);
```

Порядок вычисления параметров функции в C++ не определён. В вызове `min(x=15, x+y)` одно выражение изменяет `x`, а другое его читает.
- Если первым вычислен `x+y`, то это `10+3 = 13`. Затем `x=15`, и `min(15, 13) = 13`.
- Если первым вычислен `x=15`, то `x+y = 18`, и `min(15, 18) = 15`.

До C++17 такой код вызывает неопределённое поведение, так как `x` изменяется и читается без упорядочивания. Начиная с C++17 вычисления параметров не пересекаются, но их порядок остаётся неопределённым (unspecified). Результат зависит от компилятора. На g++ 13.3 вывод: `13`. Большинство реализаций g++ вычисляет параметры справа налево, а clang — слева направо, поэтому на нём ожидается `15`.

**Фрагмент 2 — поведение однозначное.**

```cpp
int x = 10, y = 3;
x = 15, y += x, x += y;
```

Оператор «,» имеет самый низкий приоритет, поэтому строка разбирается как три выражения. Правый операнд оператора «,» упорядочен после левого, поэтому порядок строго слева направо.
- `x=15`
- `y += x` даёт `y = 3+15 = 18`
- `x += y` даёт `x = 15+18 = 33`

Итог: `x=33, y=18`.

**Фрагмент 3 — поведение однозначное.**

```cpp
int x = 10, y = 9;
if (x > y++ && y++ > 9)
    cout << "yes" << endl;
cout << y;
```

Для `&&` вычисления идут строго слева направо. Все побочные действия левого операнда завершаются до вычисления правого.
- `x > y++`: сравнивается `10 > 9`, истина, затем `y = 10`.
- `y++ > 9`: сравнивается `10 > 9`, истина, затем `y = 11`.

Вывод: `yes` и затем `11`. Неоднозначности нет, потому что `y` изменяется в двух разных операндах `&&`, между которыми есть упорядочивание.

### Задание 2 **(2)**
*Как записать следующие строки программы на С++ в виде одного
выражения? Приведите несколько способов, в том числе с использованием операторов инкремента.*
*Проверьте работу написанных программ*
```
x=x+1;
z=z+2*x+3*y;
y=y+1;
```
*Тексты программ разместите в папке с номером задания*

**Решение**

Чтобы заменить три инструкции одним выражением, можно использовать оператор запятая. Он обеспечивает вычисление частей выражения слева направо, поэтому сначала увеличивается `x`, затем вычисляется новое значение `z` с уже увеличенным `x`, а после этого увеличивается `y`.

Первый вариант:

```cpp
x++, z = z + 2 * x + 3 * y, y++;
```

Второй вариант с префиксным инкрементом и составным присваиванием:

```cpp
(++x, z += 2 * x + 3 * y, ++y);
```

Третий вариант, использующий `+=` для увеличения переменных:

```cpp
(x += 1, z += 2 * x + 3 * y, y += 1);
```

Все три выражения сохраняют порядок исходных операций. Важно, что `x` увеличивается **до** вычисления выражения для `z`, а `y` — **после** него. Проверить результат можно, задав начальные значения `x`, `y` и `z`, выполнив исходный вариант и каждый из новых вариантов отдельно и сравнив конечные значения переменных.

### Задание 3 **(2)**
*Рассмотрите следующий фрагмент программы. Он заполняет вектор из 10 элементов единицами.*
```
std::vector<int> x(10);
for (int i = 0; i < 10;)
   x[i++] = 1;
```
*Перепишите ее так, чтобы в третьей строке использовался префиксный инкремент, но результат ее работы не изменился.*
```
std::vector<int> x(10);
for (...)
   x[++i]=1;
```

**Решение**

В исходном варианте `i` начинается с нуля, а выражение `x[i++]` сначала обращается к элементу с текущим индексом, затем увеличивает `i`. При замене постфиксного инкремента на префиксный индекс нужно сдвинуть начальное значение `i` на единицу вниз. Тогда первая итерация увеличит `i` с `-1` до `0` и запишет единицу в `x[0]`, а последняя запишет единицу в `x[9]`.

```cpp
std::vector<int> x(10);
for (int i = -1; i < 9;)
    x[++i] = 1;
```

Цикл выполняется десять раз и заполняет единицами все элементы вектора с индексами от `0` до `9`. В результате вектор такой же, как и в исходной программе.

### Задание 4 **(2)**

*Почему присваивание* ```(++x)=y``` *является синтаксически правильным, а*
```(x++)=y``` - *нет? Запишите текст сообщения об ошибке, переведите и объясните его.*

**Решение.**
- Префиксный `++x` увеличивает `x` и возвращает **lvalue** (сам объект `x`). Слева от присваивания допустим неконстантный lvalue, поэтому `(++x)=y` сначала увеличивает `x`, а потом записывает в него `y`.
- Постфиксный `x++` возвращает **rvalue**, то есть временную копию старого значения. У неё нет индивидуальности в памяти, и присваивать в неё нельзя.

Сообщение g++:
```
error: lvalue required as left operand of assignment
```
Перевод: «ошибка: в качестве левого операнда присваивания требуется lvalue». Значит, слева от `=` стоит выражение, не являющееся lvalue (здесь `x++`, rvalue).

### Задание 5 **(2)**

*Программисты на Python для обмена значений двух переменных часто пишут строку*
```
a,b = b,a
```
*Проверьте, будет ли аналогичная строка на С++ (с точкой с запятой в конце) являться синтаксически
правильной? Будет ли она обменивать значения переменных? Как в языке С++ вычисляется это выражение?*

**Решение**

```cpp
int a = 1, b = 2;
a, b = b, a;
std::cout << a << " " << b;
```

Данная запись синтаксически правильная и компилируется, однако значения переменных не меняются местами. Программа выведет `1 2`. Компилятор g++ с параметром `-Wall` также может выдать предупреждения о том, что некоторые части выражения с запятыми не выполняют полезных действий.

Это происходит потому, что в C++ запятая является оператором, а не способом обмена значениями, как в Python. Приоритет оператора присваивания выше, чем у оператора запятая, поэтому выражение можно представить так:

```cpp
(a), (b = b), (a);
```

Вычисление происходит слева направо:

1. `a` — значение переменной используется, но не изменяется.
2. `b = b` — переменной `b` присваивается её собственное значение, поэтому оно остаётся прежним.
3. `a` — последнее выражение также не изменяет переменную.

Таким образом, исходные значения `a` и `b` сохраняются.

Для правильного обмена значениями можно использовать временную переменную:

```cpp
int temp = a;
a = b;
b = temp;
```

Также можно воспользоваться готовой функцией `std::swap(a, b)`, подключив заголовок `<utility>`. Она меняет значения переменных местами без необходимости самостоятельно создавать временную переменную.

### Задание 6 **(2)**

*Проверьте работу следующего фрагмента программы*
```
  std::string s;
  for (int i=0; i<1000000; i++)
     s += 'a';
  std::cout << s.size();
```
*Измените третью строку на*
```
s=s+'a';
```
*Изменится ли что-нибудь в ее работе? Объясните результат.*

**Решение.**
```cpp
std::string s;
for (int i = 0; i < 1000000; i++)
    s += 'a';
std::cout << s.size();
```

```cpp
std::string s;
for (int i = 0; i < 1000000; i++)
    s = s + 'a';
std::cout << s.size();
```

Оба варианта выводят 1000000, поэтому конечный результат не меняется, но время выполнения может отличаться.

При использовании s + 'a' создаётся новая строка, в которую копируется старое содержимое и добавляется новый символ. Затем эта строка присваивается переменной s. Из-за этого на каждой итерации приходится повторно обрабатывать накопленные символы, что может значительно замедлить программу.

Оператор += позволяет добавлять символы к строке эффективнее, используя уже выделенную память. Таким образом, разница между вариантами заключается в скорости выполнения и количестве операций с памятью, а не в результате программы.

### Задание 7 **(2)**

*Как работает следующая программа? Как зависит результат от исходного значения?*
```
int x;
std::cin >> x;
x-->0 && x-->0 && x-->0 && x-->0 && x-->0;
std::cout << x;
```

**Решение.**
Запись `x--> 0` разбирается так: сравнивается старое значение, затем `x` уменьшается. Операторы `&&` вычисляются слева направо с сокращённым вычислением. Как только очередное сравнение ложно, оставшиеся операнды не вычисляются и их побочные действия не выполняются. Значит, `x` уменьшается на число вычисленных сравнений.

Зависимость от исходного `x`:
- `x ≥ 5`: все пять сравнений истинны, итог `x - 5`.
- `0 ≤ x ≤ 4`: после `x` истинных сравнений следующее ложно. `x` уменьшится ещё на 1, итог `-1`.
- `x < 0`: первое сравнение ложно, итог `x - 1`.

Проверка: `3 → -1`, `5 → 0`, `10 → 5`, `-1 → -2`.

### Задание 8 **(3)**

*Какое число выводит следующий фрагмент программы? Посчитайте результат без использования
вычислительной техники. Отчет должен содержать процесс вычислений.*
```
int s = 0;
for (int i = 0, j = 5;i+j <= 16;(i<j ? i : j)++)
   (s += i) += j;
std::cout << s;
```

**Решение.**
- `(i<j ? i : j)++` увеличивает **меньшую** из переменных. При `i == j` увеличивается `j`.
- `(s += i) += j` — это `s += i`, затем к результату `s` прибавляется `j`. Итого `s += i + j`.
- Условие продолжения цикла: `i + j <= 16`.

| итерация | i | j | i+j | проверка ≤16 | s после итерации |
|---|---|---|---|---|---|
| 1 | 0 | 5 | 5  | да | 0+5 = 5 |
| 2 | 1 | 5 | 6  | да | 5+6 = 11 |
| 3 | 2 | 5 | 7  | да | 11+7 = 18 |
| 4 | 3 | 5 | 8  | да | 18+8 = 26 |
| 5 | 4 | 5 | 9  | да | 26+9 = 35 |
| 6 | 5 | 5 | 10 | да | 35+10 = 45 |
| 7 | 5 | 6 | 11 | да | 45+11 = 56 |
| 8 | 6 | 6 | 12 | да | 56+12 = 68 |
| 9 | 6 | 7 | 13 | да | 68+13 = 81 |
| 10 | 7 | 7 | 14 | да | 81+14 = 95 |
| 11 | 7 | 8 | 15 | да | 95+15 = 110 |
| 12 | 8 | 8 | 16 | да | 110+16 = 126 |
| 13 | 8 | 9 | 17 | **нет** | выход |

Сумма `i + j` на итерациях образует последовательность 5, 6, …, 16. Это арифметическая прогрессия из 12 членов: `(5+16)·12/2 = 126`.

**Ответ: 126.**
